# 真实面经高频题（2025–2026）

> 本章导读：这一章不是“教科书目录”，而是把公开面经、题库和开源笔记里的高频问法去重后，按主题整理成可直接练习的题单。每题给“考察点 + 回答要点 + 常见追问”，并标注近两年的考察趋势。
>
> 重要说明：题目来自公开面经/题库的归纳，不代表任何公司的完整题库；答案均为原创整理。样本有限，“出现频次”只能说明方向，不是精确统计。

## 核心要点

- 2025–2026 的算法岗面试明显从“背定义”转向“推公式 + 算显存 + 讲项目数字”。
- 架构部分的高频核心是：RoPE、RMSNorm、Pre/Post-Norm、GQA/MLA、SwiGLU、MoE；要求能推导、能算参数量。
- 训练部分的高频核心是：LoRA/QLoRA、显存估算、ZeRO、SFT 数据与 loss mask、灾难性遗忘。
- 对齐部分的高频核心是：PPO/DPO/GRPO 的公式与区别、KL 与 β、reward hacking、RLVR。
- 推理部分的高频核心是：KV Cache 计算、PagedAttention、FlashAttention、continuous batching、量化、投机解码。
- 应用部分的高频核心是：RAG 全链路与评测、Agent 循环与工具调用、MCP、记忆、上下文工程、权限与 HITL。
- 项目部分是决定成败的主线：每个技术点后面几乎都会接一句“你们具体怎么做的、效果怎么量化”。
- 2026 新增重灾区：上下文工程、Skill/Harness、HITL 与 ACL、Token 治理与可观测性、Agentic RAG。

### 重点题补充

**Q：RoPE 的相对位置性质怎么证？**
- 二维旋转：$R(m\theta)=\begin{pmatrix}\cos m\theta&-\sin m\theta\\\sin m\theta&\cos m\theta\end{pmatrix}$。
- 正交性：$R(m)^\top=R(-m)$，可加性：$R(m)^\top R(n)=R(n-m)$。
- 因此 $(R(m)q)^\top(R(n)k)=q^\top R(n-m)k$，只依赖 $n-m$。
- 多维时对每对维度独立旋转，内积是所有对的和，仍然只依赖相对位置。

**Q：SwiGLU 的参数量账怎么算？**
- 标准 FFN：$W_1\in\mathbb{R}^{d\times4d}$、$W_2\in\mathbb{R}^{4d\times d}$，参数量 $8d^2$。
- SwiGLU：$W_1,W_3\in\mathbb{R}^{d\times d_{ff}}$、$W_2\in\mathbb{R}^{d_{ff}\times d}$，参数量 $3d\cdot d_{ff}$。
- 令 $3d\cdot d_{ff}=8d^2$，得 $d_{ff}=8d/3$。
- 实际实现会对齐到 128 的倍数，所以是近似值。

### 重点题补充

**Q：全参微调 7B 需要多少显存？**
- 参数：7B × 2 bytes（BF16）= 14GB。
- 梯度：14GB。
- Adam 状态：FP32 m/v + master weight ≈ 7B × 12 bytes = 84GB（若混合精度维护 FP32 副本）。
- 合计约 112GB，尚未算激活；实际用 ZeRO/FSDP 分片或 LoRA。
- 面试时先说明假设（精度、优化器、是否 offload），再给数量级。

**Q：DPO 的 β 太大/太小会怎样？**
- β 控制对 reference 的约束强度：β 大 → 更保守、接近 SFT，学不动；β 小 → 更激进、易过拟合偏好数据、输出退化。
- 常见范围 0.1–0.5，需在验证集上看 win rate、长度、KL。
- β 与学习率、数据质量耦合，不能孤立调。

### 重点题补充

**Q：7B 模型 32K 上下文的 KV Cache 多大？**
- 假设 32 层、8 个 KV 头、$d_h=128$、FP16。
- 每 token：$2\times32\times8\times128\times2=131072$ bytes ≈ 128KB。
- 32K：$128\text{KB}\times32768\approx4$GB。
- 70B（80 层、8 KV 头）：每 token 约 320KB，32K 约 10GB。
- 实际加上权重（7B FP16 14GB）、激活、框架开销；单卡 24GB 跑 32K 7B 很紧。

**Q：投机解码的加速比怎么估？**
- 设草稿长度 $\gamma$、接受率 $\alpha$，期望接受 token 数约为 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$。
- 加速比受草稿成本、验证成本、接受率影响；接受率低或草稿模型太慢时不划算。
- 适合：大模型 decode 受带宽限制、草稿模型远小于目标模型、输出可预测（代码/摘要）。

### 重点题补充

**Q：MCP 和 Function Calling 的区别？**
- Function Calling：模型输出“调用哪个函数、什么参数”的结构化意图，执行与权限在应用侧。
- MCP：标准化协议，统一工具/资源的发现、描述、调用，让 server 可被多个 client 复用。
- 类比：FC 是函数调用约定，MCP 是接口标准；MCP 不替代权限、沙箱、审计。
- 面试追问：为什么需要 MCP？答：工具生态碎片化、重复接入、跨应用复用。

**Q：上下文工程的压缩放在哪一步？**
- 入口：系统提示/工具定义裁剪（静态）。
- 检索后：chunk 去重、摘要、按 token 预算截断。
- 工具返回后：结构化提取、只保留关键字段、错误信息压缩。
- 对话中：滑窗 + 摘要 + 关键事实固定。
- 原则：先保留“决策所需的最小充分信息”，再压缩；压缩后要做可回答性校验。

## 11. 使用建议

1. **先按岗位筛题**：算法岗重点 3/4/5 章，应用岗重点 5/6/7 章，产品岗重点 6/8 章。
2. **每题 90 秒**：先结论，再机制，再工程代价，最后项目数字。
3. **建立错题本**：答不出的题标记“会讲/会推/会写”三档，三天后复述。
4. **不要背答案**：面试官一追问细节就会暴露；要能画图、推公式、举失败案例。
5. **结合项目**：每道技术题都准备一句“我在项目里怎么用的/见过什么坑”。
